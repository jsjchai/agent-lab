# 04 · 工具调用与业务工具设计

> 对应源文档 §7 · 代码模块 [`m04_tools.py`](../m04_tools.py) + [`common/business.py`](../common/business.py) · 运行：`../../.venv/bin/python m04_tools.py`

## 一、这是什么 / 为什么重要

工具（Tool）是 Agent 能调用的**受控能力**。源文档 §7 的核心不是「怎么让模型调工具」，
而是「怎么让工具调用安全可控」：每次重新鉴权、不信任模型身份、白名单、参数校验、调用上限、
最小数据、审计。本模块用一个 `ToolRegistry` 把这些安全规则逐条落成代码，并提供 Teaching 首期
P0 工具（只读/校验/纯计算，**不开放写工具**）。

## 二、核心概念详解

### 工具白名单
Agent 只能调用注册表里存在的工具。`publish_activity`/`delete_activity` 等写工具**根本不在注册表里**——
不是「禁止调用」，而是「不存在」，从源头杜绝越权写。

### 参数 Schema 校验
每个工具用 pydantic 模型定义参数（`OrgParams`/`SearchParams`/`DraftParams`…），非法参数在执行前拦截。

### 二次鉴权与身份不可信
**安全上下文 `SecurityContext` 来自认证链路，不采信模型生成的身份字段**。工具参数若携带
`userId/tenantId` 直接拒绝；组织访问权限由 `ctx.can_access_org(org_id)` 判定，而非模型说了算。

### 调用次数限制
按 `(task_id, tool_name)` 计数，超过 `max_calls` 拒绝——防止模型陷入工具调用死循环。

### 最小数据 + 审计
工具只返回完成任务所需的最小数据（如搜索人员只返回姓名）；每次调用（无论允许/拒绝）记入 `AuditLog`。

### P0 工具清单（源文档 §7）

| 工具 | 类型 | 说明 |
|---|---|---|
| `query_activity_rules` | read | 查询活动规则 |
| `query_rotation_snapshot` | read | 查询轮转计划快照（校验组织权限） |
| `query_org_scope` | read | 查询当前用户可访问组织 |
| `search_participants` | read | 授权范围内搜索人员 |
| `validate_activity_draft` | validate | 校验活动草稿 |
| `build_activity_draft` | compute | 构建活动草稿（纯计算） |

## 三、代码实现解析

### ToolRegistry.call：五步校验流水线

```python
# m04_tools.py
def call(self, name, ctx, args, task_id="t"):
    # 1. 白名单
    spec = self._tools.get(name)
    if spec is None:
        self.audit.record(name, ctx, {"reason": "not in whitelist"}, allowed=False)
        raise AuthError(f"工具不在白名单：{name}")
    # 2. 拒绝模型自带身份字段
    forged = _FORBIDDEN_IDENTITY & set(args)        # {userId,tenantId,user_id,tenant_id}
    if forged:
        self.audit.record(..., allowed=False); raise AuthError(...)
    # 3. 调用次数限制
    self._calls[(task_id, name)] += 1
    if self._calls[(task_id, name)] > spec.max_calls:
        raise AuthError(f"工具调用次数超限：{name}")
    # 4. 参数校验
    params = spec.params.model_validate(args)       # pydantic，非法即拦截
    # 5. 执行（handler 内部再做权限校验）+ 审计
    result = spec.handler(ctx, params)
    self.audit.record(name, ctx, {"kind": spec.kind}, allowed=True)
    return result
```

**为什么这样写**：把安全检查集中在调用入口，任何工具都自动经过五步，不依赖每个 handler 自觉。
每一步拒绝都记审计（`allowed=False`），事后可追溯。

### handler 内的二次鉴权

```python
def search(ctx, p: SearchParams):
    if not ctx.can_access_org(p.org_id):           # 组织权限由 ctx 判定
        raise AuthError("无权在该组织搜索人员")
    people = business.PARTICIPANTS.get(p.org_id, [])
    if p.keyword:
        people = [x for x in people if p.keyword in x]
    return {"participants": people}                # 最小数据：只返回姓名
```

注意 `org_id` 是**受校验的查询参数**，不在禁止身份字段之列——它能否访问由 `ctx.can_access_org` 决定。
被禁的是模型试图自带 `userId/tenantId` 来冒充身份。

### build_activity_draft：纯计算工具

```python
def build(ctx, p: SlotsParams):
    s = p.slots
    return {"title": f"{s.get('grade','')}{s.get('subject','')}{s.get('activity_type','教学活动')}",
            "activity_type": s.get("activity_type", "教研活动"), ...}
```

把 [02 归一化](02-Prompt与上下文工程.md) 后的 slots 组装成草稿，不调模型、不写库——纯函数，可测试。

## 四、工程要点与常见坑

| 现象 | 原因 | 对策 |
|---|---|---|
| 模型调用了写工具 | 注册表暴露了写能力 | P0 根本不注册写工具 |
| 模型伪造 userId 冒充他人 | 采信模型身份字段 | `_FORBIDDEN_IDENTITY` 出现即拒绝 |
| 跨租户搜索人员 | 未校验组织权限 | handler 内 `ctx.can_access_org` |
| 工具调用死循环 | 无次数上限 | `(task_id,name)` 计数 + `max_calls` |
| 非法参数执行后才报错 | 无前置校验 | pydantic `model_validate` 前置拦截 |
| 返回过多敏感数据 | 工具返回全量 | 最小数据原则（只返回姓名） |
| 越权无法追溯 | 无审计 | 每次调用记 `AuditLog`（含拒绝） |

## 五、验收与测试

`selftest()` 断言：

```python
assert reg.call("search_participants", ctx, {"org_id": "o1"})["participants"]  # 正常调用
# 以下三类必须被拦截
for bad in [跨租户 o3, 伪造 tenantId, 白名单外 delete_activity]:
    try: bad(); raise AssertionError("应当被拦截")
    except AuthError: pass
assert len(audit.denied()) >= 3                 # 拒绝有审计
assert "publish_activity" not in reg.names()    # 写工具不存在
```

对应源文档 §7 验收：越权拒绝、非法参数拦截、调用有审计、写工具不暴露。
