## 建议阅读顺序

**入门路线**（先跑通再读）：

2. 读 [01](01-LLM基础与结构化输出.md) → [02](02-Prompt与上下文工程.md) → [04](04-工具调用与业务工具设计.md)：理解「模型输出 → 校验 → 工具」的基本链路。
3. 读 [05](05-Agent工作流编排.md)：看这些如何被编排成一个有澄清/确认回环的工作流（核心）。
4. 读 [06](06-RAG与知识问答.md) + [07](07-安全治理与人工确认.md)：补检索与安全两条线。

**工程路线**（做生产化）：

## 贯穿性设计原则（反复出现，先记住）

1. **模型负责语义，代码负责边界**：小模型格式必漂移，关键字段（缺项/日期/引用）用确定性规则兜底。见 02/06/11。
2. **mock 是确定性验收基线**：`run_all`/m08 用 mock 保稳定全绿；真实模型用来观察能力边界。见 08/11。
3. **业务规则/权限/一致性用确定性断言**，LLM-as-Judge 只评表达质量。见 08。
4. **身份与写操作不交给模型**：安全上下文来自认证链路；Agent 不直接写业务表；确认凭证一次性。见 04/07。
5. **业务流程不绑定框架/供应商**：模型调用抽成 `common/llm.py`，切 mock↔真实模型业务代码不动。见 03。

## Java → Python 技术替代（详见 [项目 README](../README.md)）

| 源文档（Java） | 本项目（Python） |
|---|---|
| Spring AI ChatClient / Structured Output | openai SDK + pydantic |
| Spring WebFlux SSE | FastAPI StreamingResponse |
| LangGraph4j | LangGraph + SqliteSaver |
| Milvus | numpy 本地向量索引 |
| RocketMQ + MySQL Outbox | SQLite tasks + outbox |
