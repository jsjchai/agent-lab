# 07 · 安全治理与人工确认

> 对应源文档 §11 · 代码模块 [`m07_security.py`](../m07_security.py) + [`common/security.py`](../common/security.py) · 运行：`../../.venv/bin/python m07_security.py`

## 一、这是什么 / 为什么重要

Agent 接入真实业务，安全是底线。源文档 §11 的七条「Teaching 必须坚持」：
Agent 只做理解/生成/查询/校验/草稿；**不直接写业务表**；用户确认后由前端调既有 API；
原业务服务负责权限/规则/事务；**安全上下文来自可信认证链路，不采信模型生成的身份字段**；
Tool 层二次鉴权；**确认凭证绑定用户/租户/草稿哈希/有效期，一次性使用**。

本模块用 `common/security.py` 实现安全上下文与一次性凭证，用 `m07_security.py` 的 **12 项对抗测试**
逐条验证这些规则。验收：越权拦截率 100%、凭证不可重放、关键调用可审计。

## 二、核心概念详解

### Authentication / Authorization / Multi-tenancy
`authenticate(user_id)` 从服务端用户库取身份，构造 `SecurityContext(user_id, tenant_id, org_ids, role)`。
身份**不来自模型**。多租户隔离靠 `tenant_id`，组织权限靠 `org_ids` + `can_access_org`。

### Least Privilege（最小权限）
工具只读/校验/纯计算，不暴露写工具（见 [04](04-工具调用与业务工具设计.md)）；工具只返回最小数据。

### Prompt Injection
用户输入或检索文档试图改写系统指令。防线：输出结构校验 + 工具不采信模型身份 + 无写工具。
注入不能凭空创造出「发布/删除」能力。

### 一次性确认凭证（HITL 核心）
`ConfirmTokenStore.issue(ctx, draft)` 签发凭证，绑定五要素：用户、租户、草稿哈希、有效期、一次性标记。
`consume(token, ctx, draft)` 逐项校验，原子消费。

### Audit（审计）
`AuditLog.record(action, ctx, detail, allowed)` 记录每次工具调用（含拒绝），敏感字段不入库。

## 三、代码实现解析

### SecurityContext 与可信认证

```python
# common/security.py
@dataclass(frozen=True)
class SecurityContext:
    user_id: str
    tenant_id: str
    org_ids: tuple[str, ...]
    role: str
    def can_access_org(self, org_id): return org_id in self.org_ids

def authenticate(user_id):
    record = _USERS.get(user_id)            # 服务端用户库，非模型提供
    if record is None: raise AuthError(f"未知用户：{user_id}")
    return SecurityContext(user_id, record["tenant"], tuple(record["orgs"]), record["role"])
```

### draft_hash：凭证绑定草稿

```python
def draft_hash(draft):
    canonical = json.dumps(draft, ensure_ascii=False, sort_keys=True)
    return hashlib.sha256(canonical.encode()).hexdigest()
```

规范化 JSON 后哈希——草稿被篡改（如偷偷加主讲人）哈希即变，凭证失效。

### consume：五要素校验 + 原子消费

```python
def consume(self, token, ctx, draft):
    rec = self._tokens.get(token)
    if rec is None: raise AuthError("确认凭证不存在")
    if rec["used"]: raise AuthError("确认凭证已被使用（不可重放）")
    if time.time() > rec["expires"]: raise AuthError("确认凭证已过期")
    if rec["user"] != ctx.user_id or rec["tenant"] != ctx.tenant_id:
        raise AuthError("确认凭证与当前用户/租户不匹配")
    if rec["hash"] != draft_hash(draft): raise AuthError("草稿已被篡改...")
    rec["used"] = True                       # 一次性
```

`PersistentConfirmTokenStore`（SQLite 版）用 `UPDATE ... SET used=1 WHERE token=? AND used=0`
原子消费，`rowcount!=1` 即重放拒绝——跨进程/重启也防重放。

## 四、工程要点与常见坑

| 现象 | 原因 | 对策 |
|---|---|---|
| 模型伪造 userId 冒充 | 采信模型身份 | 身份只从 authenticate 取，工具拒绝身份字段 |
| 跨租户访问数据 | 无租户隔离 | SecurityContext.tenant_id + ACL |
| 凭证被重放 | 可重复使用 | used 标记 + 原子消费 |
| 凭证过期仍可用 | 无有效期 | expires 校验 |
| 确认后草稿被篡改 | 凭证未绑定草稿 | draft_hash 绑定 |
| 他人冒用凭证 | 凭证未绑定用户 | user/tenant 匹配校验 |
| 注入诱导写操作 | 暴露写工具 | 注册表无写工具 |
| 审计泄漏密钥 | 无差别记录 | 敏感字段脱敏 |
