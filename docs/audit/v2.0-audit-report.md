# Agent Lab V2.0 审计报告（阶段 A）

> 审计日期：2026-11-17 · 审计方式：**读取真实文件 + 实际运行测试 + 联网核实技术选型**，非依据 README 推测。
> 本报告只审计、不修改业务代码。所有结论附证据。优先级：**P0 必须解决 / P1 重要优化 / P2 后续改进**。

## 0. 核心约束（用户指定，贯穿所有阶段）

> **知识文档质量优先于文档数量。**

这条约束高于一切产出指标，具体化为可执行规则：

1. **宁缺毋滥**：不一次性铺开 docs/11-15 五个主题。先做 **11-harness-engineering 单主题试点**，
   达到教材级并通过 §7.6 质量验收、经用户确认后，再**逐个**推进下一主题。
2. **质量门禁**：每篇文档必须通过质量验收（问题背景→原理→流程图→可运行代码→代码讲解→工程取舍→真实参考）
   才能标记 Validated；未通过不得计入「完成」。**禁止用薄提纲/概念堆砌/列表表格凑数**。
3. **深度优于覆盖**：docs/01-10 升级时，优先把核心主题讲透，允许合并冗余、允许某些主题暂缓，
   不为「十个都齐」而填充空洞内容。
4. **复用优于新建**：teaching-agent/docs 已有 12 篇高质量教材，主知识体系优先**提炼/链接**这些资产，
   而非另起炉灶重写一套。
5. **数量不是 KPI**：阶段报告不以「新增 N 篇文档」为成果，而以「通过质量验收的章节 + 可运行验证 + 读者能真正理解」为成果。
6. **反模式警示**：本仓库 docs/01-10 现状（300–1100 字符提纲）正是「重数量轻质量」的反面教材，V2.0 不得复制该模式。

**对实施计划的直接影响**：阶段 C 改为「试点→验收→逐个推广」的串行门禁模式，而非并行批量产出（见 §10）。

## 1. 当前仓库总体评价

**一句话**：仓库已有一个**质量相当高的垂直样板**（`projects/teaching-agent`，11 个可运行模块 + 12 篇详细文档 + 可交互可视化 + 评测），
但**整体平台化程度低**——主知识体系 `docs/01-10` 仍是薄提纲、缺少 V2.0 要求的五大新主题、没有 Coding Agent / AI 软件工程 / 统一 Benchmark / CI/CD。
当前更像「一个优秀项目 + 一圈导航页」，而非「综合实验平台」。

**实测可运行性（本次审计实际执行）**：

| 资产 | 命令 | 结果 |
|---|---|---|
| teaching-agent 全模块 | `python run_all.py` | ✅ **11/11 通过**（约 1 秒，mock） |
| medical LangGraph | `AGENT_LLM=mock python langgraph_case_agent.py` | ✅ 评审 2 轮、修订 1 次 |
| medical CrewAI | `AGENT_LLM=mock python crewai_teaching_activity.py` | ✅ 4 任务完成 |

**真实规模**：122 个文件（排除依赖/缓存）。Python 代码集中在 `projects/teaching-agent`（m01–m11 + common + webui）
与 `code/07-frameworks/medical-education`。其余 `code/01-06、08-10` **只有导航 README，无代码**。

**成熟度现状（诚实标注）**：
- teaching-agent 各模块：**Validated**（selftest 通过），但验收基于 **mock**；真实模型仅 m11 跑过一次对比。
- medical 示例：**Validated**（mock）。
- **无任何 Production-ready 资产**；无 CI；无真实 tracing。

**对照 V2.0 四个核心问题**：

| 问题 | 当前覆盖 | 缺口 |
|---|---|---|
| 如何构建 Agent？ | ✅ teaching m01-m06 + medical 双框架 | 缺 Harness/Coding Agent 视角 |
| 如何让 Agent 可靠工作？ | ✅ m05 工作流/m07 安全/m10 可靠性 | 缺真实 tracing/AgentOps |
| 如何科学评估 Agent？ | ◐ m08 门禁/m11 对比 | 缺统一 Benchmark 平台、Harness 对比 |
| 如何让 Agent 参与软件开发并交付代码？ | ❌ 无 | **完全缺失** Coding Agent / AI 软件工程 |

## 12. 审计结论

仓库**地基好**（teaching-agent 是高质量样板，代码真实可运行），但**平台化缺口大**
