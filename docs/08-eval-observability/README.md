# 08 · 评测与可观测

**目标**：能证明「这一版比上一版强」，而不是凭感觉。

## 关键问题
- 单轮任务和多步 Agent，评测方法有什么不同？
- LLM-as-judge 靠得住吗？怎么校准它？
- 稳定性怎么测？（同一条用例跑 10 次，方差多大）
- trace 里最该看的是什么？（工具调用序列、上下文长度、失败点）

## 产出
- [ ] 20~50 条自己的评测用例，放在 `evals/`
- [ ] 一个跑分脚本，输出「分数 + 平均 token + 平均延迟 + 失败率」
- [ ] 一次 trace 回放，定位到一个具体失败原因
- [ ] 一条分数曲线（改动前后的对比）
