# 学习路线

> 原则：每个阶段都以「能跑起来的东西」收尾，不以「看完」收尾。

## 阶段一 · 打地基（约 1~2 周）

| # | 内容 | 目录 | 验收标准 |
|---|---|---|---|
| 1 | Agent / Workflow / ReAct 的边界 | [01](01-foundations/) | 能画出循环图，并说清停止条件 |
| 2 | Prompt 结构与结构化输出 | [02](02-prompt-context/) | 输出能被 `json.loads` 稳定解析 |
| 3 | 手写 function calling 循环 | [03](03-tool-use/) | 不用框架，跑通「查天气 + 多轮修正」 |

- [ ] 手写 ReAct 循环（30 行以内，无框架）
- [ ] 写一页对比：什么任务用 Workflow，什么任务才值得上 Agent
- [ ] 手写工具调用：schema → 模型决策 → 执行 → 回填 → 终止

**交付物**：`code/` 下一个 200 行以内的 mini agent，不依赖任何 agent 框架。

## 阶段二 · 补能力（约 3~4 周）

| # | 内容 | 目录 | 验收标准 |
|---|---|---|---|
| 4 | 检索与记忆 | [04](04-memory-rag/) | 能解释一次 bad case：为什么没检索到 / 为什么记错了 |
| 5 | 任务分解与反思 | [05](05-planning/) | 长任务拆成可验证的子步骤 |
| 6 | 框架选型 | [07](07-frameworks/) | 用框架重写阶段一，写出「框架省了什么/藏了什么」 |

- [ ] 给 mini agent 加一个本地知识库工具
- [ ] 加长期记忆，并设计一个「该忘就忘」的策略
- [ ] 用 LangGraph 或官方 Agent SDK 重写一版，做差异对比

**交付物**：`projects/` 里第一个能解决真实问题的小工具。

## 阶段三 · 做工程（约 4~6 周）

| # | 内容 | 目录 | 验收标准 |
|---|---|---|---|
| 7 | 多智能体编排 | [06](06-multi-agent/) | 能说清「为什么这里必须多角色」 |
| 8 | 评测与追踪 | [08](08-eval-observability/) | 有自己的评测集和分数曲线 |
| 9 | 安全护栏 | [09](09-safety-guardrails/) | 有过一次成功/失败的注入测试 |
| 10 | 成本与上线 | [10](10-production/) | 有延迟、token 成本、失败率的基线数据 |

- [ ] 建 20~50 条自己的评测用例，固定下来
- [ ] 接入 tracing，能回放一次失败运行
- [ ] 做一次压测或成本核算，写出优化前后对比

**交付物**：一个带评测报告的项目（分数 + 成本 + 已知限制）。

## 每周节奏（建议）

- 周一：读资料 + 写笔记骨架（`docs/`）
- 周二~周四：写代码验证，卡住就记日志（`docs/journal/`）
- 周五：整理笔记结论 + 更新本页勾选 + 更新 [docs/README.md](README.md) 状态
- 周末：只做「回看 bad case」，不学新东西
